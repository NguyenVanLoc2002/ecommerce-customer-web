# page-blueprints.md

## 1. Purpose

This document defines page-level blueprints for `customer-app`.

Blueprints ensure consistency in:
- structural hierarchy
- section rhythm
- CTA placement
- browsing behavior
- conversion flow design

These are implementation templates, not rigid wireframes.

---

## 2. Shared Page Principles

1. Each page must have a clear primary goal.
2. Browsing pages should feel easy and modular.
3. Conversion pages should feel calm and trustworthy.
4. Repeated page types must reuse repeated structures.
5. Promotional expression must not break UX consistency.

---

## 3. Standard Page Anatomy

Most customer pages should use:
1. page shell
2. hero or page intro where relevant
3. contextual controls
4. primary content zone
5. supporting content zone
6. footer and system states

---

## 4. Homepage Blueprint

### Structure
1. hero section
2. featured categories / collections
3. promotional or campaign block
4. featured products
5. trust / brand / service section
6. additional discovery modules
7. footer

### Rules
- above-the-fold value must be clear
- hero may use richer visual treatment and optional lightweight 3D
- sections must feel modular and scroll-friendly
- CTAs must remain obvious

---

## 5. Category / Listing Blueprint

### Structure
1. page intro / category header
2. filter and sort controls
3. product grid
4. optional merchandising block
5. pagination or load-more logic
6. empty/loading/error states

### Rules
- product browsing must stay fast and uncluttered
- filters should be powerful but not overwhelming
- product card consistency is critical
- mobile/responsive behavior must remain practical

---

## 6. Product Detail Blueprint

### Structure
1. media gallery / hero product zone
2. purchase info block
3. variant and option selection
4. CTA block
5. product detail/content sections
6. related or recommended products
7. trust/support blocks

### Rules
- buy-critical information must appear immediately
- media and content should feel premium
- optional 3D showcase may appear only if lightweight and useful
- sticky buy summary may be used where helpful

---

## 7. Cart Blueprint

### Structure
1. page header
2. cart items list
3. summary panel
4. promo/note block if relevant
5. checkout CTA
6. empty state

### Rules
- total and CTA must remain clear
- quantity and remove interactions should be lightweight
- visual noise should stay low

---

## 8. Checkout Blueprint

### Structure
1. progress indicator
2. address section
3. shipping section
4. payment section
5. order summary
6. final CTA and trust messaging
7. validation/error feedback

### Rules
- prioritize confidence and clarity
- reduce distractions
- avoid visually rich effects in critical form sections
- motion should be minimal and purposeful here

---

## 9. Account Blueprint

### Use for
- profile
- orders
- saved items
- addresses
- account settings

### Structure
1. page header
2. sub-navigation
3. main content area
4. empty/loading/error states

### Rules
- keep account screens clean and task-focused
- preserve the same visual family as the rest of the app
- order history/status readability must stay strong

---

## 10. Shared Section Patterns

### Page intro pattern
Supports:
- title
- subtitle
- breadcrumb if needed
- CTA if needed

### Section block pattern
Supports:
- title
- description
- content area
- optional action link

### Summary panel pattern
Supports:
- totals
- status
- key notes
- CTA

These patterns must repeat consistently across pages.

---

## 11. Empty, Loading, Error States

Every blueprint must define:
- loading state
- empty state
- error state
- special conversion-blocked state where relevant

### Empty state should include
- concise title
- explanation
- next step or browse CTA

### Loading state should prefer
- skeletons for cards, grids, and structured sections
- subtle inline loaders for small actions

---

## 12. Responsive Rules

Customer pages must explicitly adapt:
- hero layout stacks cleanly
- product grids change density by breakpoint
- summary panels become sticky or stacked
- filters become drawers/sheets on small screens
- detail layouts reorganize predictably

---

## 13. Motion Guidance at Page Level

Use:
- subtle section reveal
- image/content polish
- filter result transitions
- smooth sticky behavior
- restrained route-level intro

Avoid:
- overwhelming animated storytelling on every page
- decorative motion in cart/checkout-critical areas

---

## 14. 3D Placement Rules

Most appropriate for:
- homepage hero
- featured campaign section
- premium product storytelling
- brand section

Not suitable for:
- checkout forms
- cart summary
- dense account pages
- utility/error states

---

## 15. Final Rule

A customer page is successful when it:
- supports discovery clearly
- feels premium and cohesive
- keeps CTA hierarchy obvious
- improves trust and conversion without visual overload
